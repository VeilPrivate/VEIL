# VEIL Double Ratchet — Signal spec conformance map (b185)

Status: b185 staged patch over the b184 tree. This document maps the engine
(`vendor/crypto-core/src/ratchet.ts`, protocol tag `veil-ratchet-4`) to the
Signal Double Ratchet specification (rev. 4) and states, honestly, where VEIL
deviates.

Owner decision (Oct 2026): Signal publishes no official test-vector file for
the Double Ratchet. VEIL's acceptance bar is therefore **(a)** the frozen
self-published deterministic vector suite
(`repro/vectors/dr1_vectors.json`, generated by `repro/gen_dr_vectors.ts`,
verified by `repro/b185_dr_vectors.test.ts`) and **(b)** the spec-conformance
assertions below. Any byte-level engine change must fail the suite.

| KDF_RK(RK, DH_out) = HKDF(salt=RK, ikm=DH) | `deriveRoot`: HKDF-SHA256, ikm = `DH_out ‖ pqSecret`, 64-byte output split (RK', CK) | conformant + PQ extension (vector: `rootKeyOut`, `rootKeyPqOut` — the PQ secret demonstrably changes the output) |
| KDF_CK(CK): mk=HMAC(ck,0x01), ck'=HMAC(ck,0x02) | `advanceChain` | byte-for-byte spec (vector: `ckMessageKey`, `ckNext`) |

## Deviations (all deliberate, all documented)

CORRECTION (Oct 11, b185-r2): an earlier draft of this document listed the
two-stage root as a deviation. That was wrong. The Signal spec's DHRatchet is
itself a two-stage derivation — `KDF_RK` with the CURRENT key pair, then
`GENERATE_DH` and a second `KDF_RK` with the FRESH pair — and that is exactly
what `stepRatchet` implements (`rootA`/`rootB`). The engine's ratchet-step
structure is spec-conformant. The post-step root being non-replayable is
inherent to spec DR (GENERATE_DH is random), not a custom feature; the vector
suite asserts the deterministic half accordingly.

The actual deviations from the spec text, each deliberate:

1. **PQ-extended KDF_RK (owner-directed, the product's differentiator).**
   Every KDF_RK input is `DH_out ‖ PQ_secret` instead of `DH_out`: the
   handshake mixes an ML-KEM-768 key agreement; each step mixes (a) the
   sender's ML-KEM re-key ciphertext decapsulated by the receiver
   (`pqct` → rootA) and (b) the receiver's ML-KEM encapsulation back to the
   sender's next step key (`pq` → rootB). Each side generates a fresh
   ML-KEM-768 step keypair every step (per-step PQ re-key). This is a
   self-contained, labeled extension of the spec's KDF_RK input; the ratchet
   structure around it is untouched spec.

2. **Session establishment** is VEIL's invite/contact ceremony (hybrid
   ECDH P-256 + ML-KEM-768, fingerprint verification) rather than X3DH; the
   ratchet consumes its outputs from the same entry points
   (RatchetInitAlice/Bob equivalents).

3. **Epoch replay guard** (`seenRemotePubs`): a header replaying an
   already-replaced remote pub is rejected outright, tightening the spec's
   implicit single-previous-epoch window.

4. **Envelope replay guard** (`processedIds`): idempotent delivery of a
   duplicated envelope id (spec defers replay to the AEAD layer).

5. **Header superset**: `v/rp/pn/n/pq/pqct` — the spec's `dh/pn/n` plus
   protocol tag and PQ fields; also AES-GCM with the full header as AAD.

Audit posture: the ratchet step, chain advancement, skipped-key handling and
desync guards are spec Double Ratchet; the PQ extension is the single
product-specific cryptographic element and is fully specified above.

## Vector suite contents (all frozen in dr1_vectors.json)

- KDF_CK / KDF_RK / PQ-mixed KDF_RK known-answers (fixed inputs → fixed bytes)
- ML-KEM-768 encap/decap known-answer (fixture ships a throwaway KAT keypair)
- 12-op snapshot-chain transcript: six recorded turns (ordered sends,
  reply-rotations, held out-of-order delivery, duplicate/replay) replayed
  link-by-link with byte-for-byte equality on every deterministic field
- Cross-epoch straggler scenario (the b185 fix): E2 envelope delivered before
  E1 stragglers; pre-b185 these threw "Stale ratchet header" and were lost
  forever — verified by reverting the fix during the build and watching the
  scenario fail exactly that way
- Fail-closed: unknown protocol tag rejected with no state damage; counter
  rewind/oversoot rejected
